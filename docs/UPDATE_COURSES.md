# Обновление сервера: версия «до курсов» → версия с курсами

Документ для того, кто будет обновлять сайт (человек или нейросеть). Его можно передать целиком: здесь всё,
что нужно знать о сделанных изменениях и о том, как безопасно выкатить их на сервер.

## 1. Исходное положение

- **Проект:** InfoEGE — закрытая платформа репетитора по ЕГЭ по информатике (Spring Boot 3, Java 21, PostgreSQL 16,
  Flyway, Thymeleaf). Репозиторий: `https://github.com/Vorozhtsov-Anton-Aleksandrovich/infoEGE`, ветка `main`.
- **На сервере (VPS, Ubuntu 24.04)** работает **старая версия — до появления курсов**. В её базе уже есть
  **ученики, задания, работы и результаты — их нельзя потерять**.
- Сервер развёрнут по `docs/DEPLOY.md`: три контейнера из `docker-compose.prod.yml` — `caddy` (HTTPS),
  `app` (приложение), `db` (PostgreSQL). Папка проекта на сервере — `/opt/infoege`, настройки — в `/opt/infoege/.env`.
- Данные лежат в Docker volume: `infoege_db-data` (база), `infoege_app-files` (загруженные файлы заданий),
  `infoege_caddy-data` (сертификаты). Имя volume начинается с имени папки проекта (`infoege`).

## 2. Что изменилось в новой версии

Всё ниже уже сделано на компьютере разработчика, все тесты проходят (`./mvnw verify`: 214 тестов, 0 ошибок).

### Раздел «Курсы» (вкладка у ученика и преподавателя)
Курсы хранятся **в коде** (`src/main/resources/courses/<курс>/`), а не в базе. Три курса, по порядку:

1. **«Основы информатики для ЕГЭ»** — 10 уроков теории (информация, системы счисления, логика, Фано, пароли,
   картинки и звук, графы, IP), 76 задач, 15 интерактивных тренажёров прямо в уроках.
2. **«Excel для ЕГЭ»** — 10 уроков (с нуля до заданий 3, 9, 18, 22), 67 задач, к задачам — xlsx-файлы для скачивания.
3. **«Python для ЕГЭ»** — 13 уроков, 72 задачи; код ученика выполняется прямо в браузере (Pyodide).

Типы задач: программа на Python, короткий ответ (целое, число, текст, два числа), выбор варианта,
таблица истинности, сопоставление графа с таблицей. Ответы проверяет **сервер**, правильные ответы в браузер
не отправляются. Подробный разбор открывается после решения или после 3 неудачных попыток.
Прогресс: у ученика — «решено X из Y» и «Продолжить»; у преподавателя — «Курсы» → курс → «Прогресс учеников».

### Другие изменения
- **Сложность заданий банка (1–5) показывается цветом** (зелёный → красный): в банке заданий, в подборках,
  в предпросмотре и во время решения в тренажёре. **В вариантах сложность скрыта**: вариант имитирует экзамен.
- **Карта активности ученика** на главной учитывает и задачи курсов: каждая задача курса — один раз в день.

### Что НЕ менялось
- Вход, ученики, приглашения, банк заданий, подборки, варианты, тренажёр, результаты — работают как раньше.
- Настройки `.env` — новых переменных **нет**, старый `.env` подходит без изменений.
- `docker-compose.prod.yml`, `Caddyfile`, `Dockerfile`, скрипты бэкапа — без изменений.

## 3. Что произойдёт с базой данных

База обновляется автоматически при старте приложения (Flyway). Новая версия содержит миграции `V1`…`V8`;
Flyway применит **только те, которых ещё нет** на сервере. Для версии «до курсов» это, скорее всего, только `V8`
(возможно, ещё `V5`–`V7`, если версия на сервере совсем старая).

| Миграция | Что делает | Существующие данные |
|---|---|---|
| V5 | `ALTER TABLE attempt ADD COLUMN manual_updated_at` | не трогает |
| V6 | расширяет допустимые значения режима показа результатов; добавляет счётчик проверок (по умолчанию 0) | не трогает |
| V7 | добавляет настройку «пауза» (по умолчанию выключена) | не трогает |
| **V8** | **создаёт две новые пустые таблицы** `course_task_attempt` и `course_task_status` (прогресс по курсам) | не трогает |

Ни одна миграция ничего не удаляет и не изменяет существующие записи. Таблица `users` (ученики, логины, пароли)
не изменяется. **Ученики сохраняются.**

Проверить, какие миграции уже стоят на сервере (из `/opt/infoege`):

```bash
docker compose -f docker-compose.prod.yml --env-file .env exec db \
  psql -U "$(grep ^POSTGRES_USER .env | cut -d= -f2)" -d "$(grep ^POSTGRES_DB .env | cut -d= -f2)" \
  -c "select version, description, success from flyway_schema_history order by installed_rank;"
```

## 4. Порядок обновления

### Шаг 0. Слить ветку `courses` в `main`
Все изменения закоммичены и лежат на GitHub в ветке **`courses`** (4 коммита поверх `main`). Сервер забирает код
из `main`, поэтому ветку нужно слить:

- на GitHub: `https://github.com/Vorozhtsov-Anton-Aleksandrovich/infoEGE/pull/new/courses` → создать pull request →
  дождаться зелёного CI → **Merge**;
- или локально: `git checkout main && git merge courses && git push origin main`.

⚠️ **Автодеплой.** В `.github/workflows/deploy.yml` настроено: после успешного CI на `main` образ собирается и сам
выкатывается на сервер — **если** в Settings → Secrets and variables → Actions задана переменная `DEPLOY_HOST`.
Тогда слияние в `main` сразу обновит сервер, **без бэкапа**. Поэтому:
- сначала проверить, задан ли `DEPLOY_HOST` (GitHub → Settings → Secrets and variables → Actions → Variables);
- если задан — **сначала сделать бэкап на сервере (шаг 1)**, потом сливать; шаги 2–3 выполнит автодеплой,
  останется проверка (шаг 4);
- если не задан — сливать можно когда угодно, сервер обновляется вручную шагами 1–4.

### Шаг 1. На сервере: бэкап (обязательно)

```bash
ssh deploy@IP_СЕРВЕРА
cd /opt/infoege
scripts/backup.sh
ls -lh /var/backups/infoege/      # должен появиться свежий архив infoege-ДАТА.tar
```

### Шаг 2. Новый код

Если сервер ставили через git (вариант А в DEPLOY.md):

```bash
git status        # локальных изменений быть не должно (кроме .env, он в .gitignore)
git pull
```

Если ставили архивом (вариант Б): распаковать новый архив **в ту же папку `/opt/infoege`**, поверх старой,
**не затирая `.env`**.

### Шаг 3. Пересобрать и перезапустить

```bash
docker compose -f docker-compose.prod.yml --env-file .env up -d --build
docker compose -f docker-compose.prod.yml --env-file .env logs -f app     # выход — Ctrl+C
```

В логах должно быть: применение миграции (`Migrating schema ... to version "8 - course progress"` — если её не было),
строки `Курс «informatics-ege»: уроков 10, задач 76`, `Курс «excel-ege»: уроков 10, задач 67`,
`Курс «python-ege»: уроков 13, задач 72` и `Started InfoEgeApplication`.

Сборка образа скачивает зависимости Maven и Pyodide (~13 МБ) — нужен интернет. При 2 ГБ RAM без swap
сборка может упасть с `Killed`: добавить swap (DEPLOY.md, шаг 1) и повторить.

### Шаг 4. Проверка
1. Сайт открывается, вход преподавателем работает.
2. **«Ученики» — все ученики на месте.** Их работы и результаты — тоже.
3. «Курсы» — три курса: «Основы информатики», «Excel», «Python».
4. В Excel-курсе у задачи кнопка «Скачать файл» скачивает xlsx.
5. Под учеником (или преподавателем) решить пару задач курса — статус задачи становится «решена».

## 5. Чего делать нельзя (иначе данные пропадут или «исчезнут»)

- **`docker compose down -v`** — флаг `-v` удаляет volume с базой. Обычные `up -d --build`, `restart`, `down` без `-v` безопасны.
- **Разворачивать новую версию в другую папку** (не `/opt/infoege`) — Docker создаст новую пустую базу
  с другим именем volume; сайт будет пустым (старая база не удалится, но будет не подключена).
- **Затирать или менять `.env`** — в нём пароль базы. Новых переменных в новой версии нет.
- **`docker volume rm`, `docker system prune --volumes`** — удаляют данные.

## 6. Если что-то пошло не так

- Приложение не стартует: смотреть `docker compose ... logs app`. Ошибки контента курсов перечисляются списком
  при старте (`Ошибки в контенте курсов: ...`) — значит, в репозиторий попало не всё (`git status` на компьютере
  разработчика, закоммитить недостающее).
- Откатиться на старую версию кода: `git log --oneline` → `git checkout <старый коммит>` → `up -d --build`.
  Миграции назад не откатываются, но новые таблицы `V8` старой версии не мешают
  (Hibernate проверяет только свои таблицы).
- Восстановить данные из бэкапа шага 1 (заменяет текущую базу содержимым архива):
  `scripts/restore.sh /var/backups/infoege/infoege-ДАТА.tar`.

## 7. Справка: где что лежит в коде

| Что | Где |
|---|---|
| Контент курсов (уроки, задачи, картинки, xlsx) | `src/main/resources/courses/{informatics-ege,excel-ege,python-ege}/` |
| Загрузка и проверка курсов | `src/main/java/.../course/` (`CourseRegistry`, `CourseMarkdown`, `CourseCheckService`, `CourseAnswers`) |
| Генераторы задач и проверка ответов (только для разработки, на сервер не нужны) | `course-tools/` |
| Скриншоты, которые ещё можно добавить в Excel-курс | `SCREENSHOTS_TODO.md` (пока файла нет, в уроке ничего не выводится) |
| Деплой с нуля | `docs/DEPLOY.md` |

На сервер **не нужно** ставить Python, LibreOffice или openpyxl — они нужны только для генерации задач на компьютере разработчика.
